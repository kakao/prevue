# 뷰어 개발

`viewer-src/`가 HTML·JS·CSS 원본과 React·TypeScript·Storybook을 갖는다. Node 버전은 `.node-version`·`.nvmrc`, 의존성은 `package-lock.json`으로 고정한다. 설치본은 커밋된 `plugin/viewer/`만 받아 Node 없이 실행한다.

```sh
cd viewer-src
npm ci
npm run build
npm run typecheck
npm run check
npm run storybook
```

저장소 루트에서는 `sh tools/gen-viewer.sh [--check]`로 생성한다. `--check`는 임시 디렉터리에 다시 만들고 파일 목록과 바이트를 비교하며 원본·설치본을 고치지 않는다. Storybook 정적 빌드는 `npm run build-storybook`이다.

`plugin/viewer/tokens.css`·`strings/*.json`·`js/resize-scene.js`·`prevue.svg`는 손으로 고치는 소스로 남는다. 나머지 설치본은 생성물이다. HTML · CSS 원본과 DOM을 쥐지 않는 기존 모듈(`api` · `store` · `strings` · `messages` · `capsule` · `board` · `motion`)은 `legacy/`에 있고 날값 린트의 대상이다. 준비 서버의 허용 경로와 `/js/resize-scene.js`의 직접 import를 유지하므로 기존 모듈은 같은 URL로 복사하고 React 입구만 Vite로 묶는다. 입구는 셋이다 — 뷰어 `js/viewer.js`(`src/main.tsx`), 준비 페이지 `js/preparation-start.js`(`src/preparation/entry-start.ts`), 둘이 함께 쓰는 준비 장면 `js/preparation-scene.js`(`src/preparation/entry-scene.ts`, 브라우저 검사가 이 주소에서 `createScene`을 import한다). React는 `js/react.js` 한 벌을 두 페이지가 함께 쓴다 — 입구마다 실으면 NFR-21 크기 상한을 넘는다. 준비 서버(`plugin/cli/prevue_prepare.py`)가 내주는 JS는 `/js/preparation*` · `/js/strings.js` · `/js/messages.js` · `/js/react.js`뿐이라 다른 청크가 생기면 준비 화면이 뜨지 않는다 — 청크 이름은 해시 없이 `js/[name].js`이고 준비 장면 입구는 함께 쓰는 모듈을 덧붙여 내보낸다(`preserveEntrySignatures`). React 쪽이 부르는 `legacy/js/` 모듈은 모두 번들 밖(external)이다 — 사본이 번들에 들면 사전·마지막 상태·캡슐·전환 중 여부가 두 벌이 된다. `motion.js`는 그 전환 상태를 `board.js` · `resize-scene.js` · 컴포넌트가 함께 쓰므로 번들에 넣지 않는다. 타입은 옆의 `.d.ts`가 갖고 설치본에는 복사하지 않는다. 손으로 고치는 `resize-scene.js`도 타입(`legacy/js/resize-scene.d.ts`)만 여기 두고 본체는 `plugin/viewer/js`의 그 주소로 부른다 — Storybook은 같은 파일로 별칭을 건다(`.storybook/main.ts`).

`src/contract-state.ts`는 다섯 `viewer.state.*.json`의 schema에서 생성한다. null·빈 목록만 있는 예제가 실행 상태 전체를 뜻하지 않으므로 `src/state.ts`에서 `BrowserState`·`BrowserMapper`·`StatusMapper`에 맞춰 메시지·크기·자세와 nullable 필드를 보완한다. SSE에만 있는 `boot`도 여기에 있다.

`main.tsx`가 연결(`src/session.ts`의 `startViewer`)을 한 번 시작한다. 영역 사이의 자리는 마크업이 정하므로 React가 맡은 영역은 `index.html`에 바깥 요소만 두고(`#app`·`#status`·`#helpBtn`·`#back`·`#wsTitle`·`#seg`·`#railList`·`#railOpen`·`#staleBar`·`#buildNotice`·`#startView`·`#vacantView`·`#cards`·`#strip`·`#chooser`·`#qoSheet`·`#help`) 안을 포털로 그린다. 바깥 요소의 속성(`#bar.busy`·`#rail[hidden]`·`#boardView[hidden]`·`#focusView[hidden]`·`body.rail-on`·`body.stale`·`body.ws` 등)은 그 컴포넌트가 효과에서 맞춘다. Storybook에서는 컴포넌트가 같은 바깥 요소를 스스로 그린다.

한 장의 정적 껍데기 — 장면(`#resizeScene`) · 무대(`#stage` · `#shot` · 박스) · 검사 패널의 칸(`#pnPick` · `#pnSl` · `#devCtl`) — 는 `src/components/WorkspaceShell.tsx`의 JSX가 원본이지만 런타임의 React가 그리지 않는다. 번들 밖의 `resize-scene.js`와 `src/workspace/focus.ts`가 그 요소를 쥐고 계속 고치고, 접기 하네스(`tests/viewer/fold.mjs`)가 설치본 `index.html`의 마크업을 그대로 읽기 때문이다. 그래서 빌드가 `src/prerender.tsx`를 SSR로 묶어 `renderToStaticMarkup`한 마크업을 `index.html`의 `<!-- prerender:stage -->` · `<!-- prerender:panel -->` 자리에 넣는다. 미리 그릴 때는 언어를 몰라 글을 비우고 `data-t` · `data-t-<속성>`만 남긴다 — 페이지에서 `strings.js`가 채운다. 런타임 React는 그 안의 바깥 요소(`#zoomCtl` · `#workspaceLoading`)에 움직이는 부분(`ZoomControls` · `WorkspaceLoading`)만 그린다. 스트림 `<img id="shot">`는 그래서 늘 붙어 있고 `src`는 `focus.ts`만 쓴다 — 다시 붙이거나 React가 `src`를 가지면 MJPEG 연결이 새로 열린다.

`session.ts`의 `apply`가 버전·전환(탭 · 작업 공간 여닫기의 틀 모프)을 고른 뒤 React 루트의 `apply(state, holdStatus)`를 부른다. React는 View Transition 스냅숏 전에 동기 커밋하고, 맡은 영역의 효과가 먼저 돈 뒤 레이아웃 효과에서 `drawScreens`가 apply마다 한 번 스트림 · 틀 · 스크롤처럼 그린 뒤에 재야 하는 것을 한다. 크기를 바꾸는 동안 상태 알약을 그대로 둘지는 `session.ts`가 정한다(`holdStatus`). 한 장의 동작(스트림 붙이기 · 좌표 · 확대 · 틀 모프 · 브라우저 뒤로 가기)은 `src/workspace/focus.ts`의 `createWorkspace`가, 크기 · 기기 전환은 `resize.ts`가, 터치 · 휠은 `input.ts`가 갖는다. 작업 공간은 미리 그린 껍데기의 요소를 쥐므로 `main.tsx`가 처음에 만들어 React 루트와 `startViewer`에 넘긴다. 확대 줄 · 첫 장 대기 · 꼬리표처럼 뷰어가 재고 정한 표시 상태는 `src/workspace/view.ts`의 작은 저장소가 갖고 컴포넌트가 구독한다 — Storybook은 그 저장소에 값을 넣어 그린다. 캡슐의 내용은 `legacy/js/capsule.js`의 DOM 없는 저장소가 갖는다 — 기존 모듈이 그리로 알리고 `NotificationCapsule`이 구독한다. 단축키 표(`src/shortcuts.ts`)는 디스패치와 도움말이 함께 쓴다. 보드의 브라우저 쪽 상태(키보드 커서 · 돌아온 카드 · 빠른 열기에서 고른 함수 · 카드 트리)도 같은 방식으로 `legacy/js/board.js`가 갖고 `PreviewBoard`가 구독한다. 보드는 레일이 접히고 펴진 뒤 같은 레이아웃 효과에서 `#boardView`를 보이고 묶음 배율을 잰다 — 기존 화면의 스크롤 복원과 `applyReveal`이 그 폭 위에서 돈다. 카드 그림의 `src`는 JSX가 갖지 않고 주소가 바뀔 때만 `swapImage`로 갈아 끼운다(크로스페이드). 가리키기(`src/workspace/point.ts`)는 보드 카드와 한 장이 함께 쓴다 — 박스의 자리는 거기서 재서 그리고, 꼬리표의 안은 `PointOverlay`가 그 박스의 `.tag`에 포털로, 후보 고르기는 `ChoicePopover`가 `#chooser`에 그린다. 카드는 자리만 만들고 `pointCard`가 이벤트를 단다. 작업 공간 · 가리키기 모듈은 사전(`strings.js`)을 부르므로 컴포넌트는 그것을 import하지 않고, 카드 열기 · 가리키기 · 확대는 `main.tsx`가 동작으로 넘긴다. 빠른 열기(`src/components/QuickOpen.tsx`)는 열림·목록·최근 연 파일을 모듈이 갖고, 도움말처럼 바깥 요소(`#qoSheet`·`#qoCurtain`·`#startView`)의 `hidden`·클래스를 레이아웃 효과와 여닫는 함수에서 바로 바꾼다 — 고른 파일의 새 화면을 그리는 그 커밋에서 팔레트가 걷혀야 한다. 검색 상자 `FileSearch`는 한 벌이라 시작 화면이면 `#startView`, 아니면 `#qoSheet`에 선다. 입력 `#q`는 React가 값을 갖지 않는다 — 브라우저 검사가 값을 넣고 `input` 이벤트를 보내면(`tests/viewer/preparation.mjs`) React의 `onChange`가 받지 않는다. 매칭은 `src/match.ts`의 순수 함수다. 준비 화면(`src/preparation/`)은 `main.tsx`가 첫 상태보다 먼저 세우고(`prepareViewer`), 기존 화면이 보드를 다 놓은 뒤 같은 레이아웃 효과에서 상태를 넘긴다 — 가운데 카드를 배치로 고른다. 끊김을 준비 실패로 알리고 다시 시작 알림을 받지 않는 일은 `startViewer`의 `prepared`로 넘긴다. 장면의 마크업(`PreparationScene` · `PreparationProgress`)은 React가 `flushSync`로 한 번 그리고 다시 그리지 않으며, 단계 글 · 막대 · 매 프레임의 부유 값 · Web Animations는 장면 컨트롤러(`scene.tsx`)가 요소에 쓴다 — 뷰어에서는 `ViewerRoot`의 커밋 안에서 불려 React 갱신이 그 자리에서 반영되지 않는데, 단계를 바꾼 바로 뒤의 `fit()`이 바뀐 글의 높이를 잰다. 그래서 장면은 React 커밋 밖에서 띄워야 한다(Storybook은 효과가 끝난 뒤 띄운다). 준비 스타일 `preparation.css`는 준비 서버가 그 이름으로 내주므로 컴포넌트가 import하지 않고 두 HTML이 링크한다.

React는 그린 요소에 열거되는 내부 키를 단다. 브라우저 검사가 레일 줄(`.rt`)을 값으로 돌려받으므로(`tests/viewer/quickopen.mjs`) 그 줄과 빠른 열기 상자의 요소는 키의 열거를 끈다(`hideReactKeys`). Storybook은 데몬 연결 없이 계약 JSON과 실제 사전을 읽는다.

조립 계획과 방향은 볼트의 `Prevue 기획`·`Prevue UX 설계`·`Prevue 비주얼 디렉션`이 갖는다. 스토리의 컴포넌트 이름은 UX 설계의 목록을 따른다. 현재는 `재료/Tokens`·`재료/Messages`·`재료/StateExamples`·`공통/ViewerRoot`·`공통/ProjectHeader`·`공통/StatusPill`·`공통/FileRail`·`공통/StaleBanner`·`공통/BuildNotice`·`공통/NotificationCapsule`·`파일/StartScreen`·`파일/QuickOpenPalette`·`파일/FileSearch`·`파일/VacantTab`·`보드/PreviewBoard`·`보드/PreviewGroup`·`보드/PreviewCard`·`작업공간/Workspace`·`작업공간/WorkspaceHeader`·`작업공간/PreviewStage`·`작업공간/WorkspaceLoading`·`작업공간/ResizeScene`·`작업공간/Ruler`·`작업공간/SizePicker`·`작업공간/CustomSizeSliders`·`작업공간/DevicePosture`·`작업공간/ZoomControls`·`가리키기/PointOverlay`·`가리키기/ChoicePopover`·`도움말/ShortcutHelp`·`준비/PreparationScreen`·`준비/PreparationScene`·`준비/PreparationProgress`가 있고, 기본 부품은 Tokens 아래에서 확인한다. `재료/Tokens`는 옛 디자인 시스템 견본을 흡수했다 — 색 역할과 풀린 값 · 대비 표를 라이트 · 다크로 나란히 두고, 대비 표의 쌍과 계산은 `tests/viewer/contrast-pairs.json`·`contrast-measure.ts`를 그대로 읽는다(미달 0은 `tests/viewer/contrast.mjs`가 지킨다). 화면 스토리의 상태는 계약 예제와, 보드 · 빠른 열기의 경우 `stories/pearl/`의 실제 보드 · 목록뿐이라 낡음 줄·바쁨·오류·외부 빌드 대기처럼 그 둘에 없는 모양은 스토리에 없다. 준비 화면의 요청 상태에는 계약 JSON이 없어 스토리가 준비 서버의 단계 값(`project` · `environment` · `render`)과 실패 사전 키, pearl 보드의 그림으로 같은 장면 컨트롤러를 띄운다. `stories/pearl/`은 `fixtures/pearl`의 `PearlPreviews.kt` 보드 30장을 이 체크아웃의 데몬에서 받은 상태의 `board`와 JPG, 같은 데몬의 빠른 열기 목록(`preview-files.json`)이다. 최근 연 파일은 브라우저에만 남는 기록이라 스토리가 그 목록의 경로로 둔다. 한 장 스토리의 무대에는 계약 예제 focus · single의 같은 자리(첫 카드)의 pearl 그림을 담고, `작업공간/Workspace`의 Device는 `resize-scene.js`를 페이지처럼 띄워 그 그림을 기기 틀에 담는다(데몬이 없어 크기를 골라도 새 그림은 오지 않는다). 배율 · 첫 장 대기는 뷰어가 재는 값이라 `view.ts` 저장소에 넣고, 꼬리표의 멘션은 계약 예제 choice의 파일 · 후보 경로로 짓는다. 데몬을 `tests/viewer/README.md`처럼 띄운 뒤 `node capture-pearl.mjs <뷰어 URL>`로 다시 뜬다(macOS의 `sips`로 줄인다).
