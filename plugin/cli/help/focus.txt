prevue focus <index> --on|--off
prevue focus <index> --size original|narrow|foldable|<W>x<H>
prevue focus <index> --device <device> [--folded] [--orientation portrait|landscape-left|landscape-right]
prevue focus <index> --device-insets on|off
prevue focus <index> --system-ui annotated|on|off

Attaches a task to the card to make it interactive (--on) and back to the board (--off) — also for a card entered by show <FQN>. While it is on, other cards are redrawn on a separate task
once input has been quiet for a second — until they all are, wait answers complete:false. Turning it off draws whatever is still old.
The person may have turned it on in the viewer — before turning it off, consider whether the person is using it.

--size · --device change the interactive card's screen size. They don't edit the source — the size survives saves, and goes back when turned off or when the tab changes.
Given to a card already on, they redraw at that size without turning interactive off (the interaction state starts over). It is the same setting as the size the person picks in the viewer.
  --size narrow 320x640dp · foldable 673x841dp · <W>x<H> is 240~1600dp · original removes the override
  --device changes size and density together. The foldable devices are duo · fold8 · ultra · pixelfold
    Android  s26(Galaxy S26) · pixel9(Pixel 9) · fold8(Galaxy Z Fold8) · ultra(Galaxy Z Fold8 Ultra)
             · pixelfold(Pixel 9 Pro Fold) · tablet(Pixel Tablet)
    iPhone   ip17(iPhone 17) · ipair(iPhone Air) · ip17pm(iPhone 17 Pro Max) · duo(iPhone Duo)
  --folded the folded screen (cover) · --landscape the device rotated from its natural orientation — devices only. Without them it is unfolded in its natural orientation
    A phone rotated is landscape; a screen that is naturally landscape (tablet · unfolded fold8) rotated is portrait. status's widthDp · heightDp give the actual orientation
--orientation selects an absolute direction on any device, including both foldable screens. The viewer uses the same three-direction menu.
  --landscape keeps its legacy meaning above; do not combine it with --orientation.
--device-insets toggles the system bar and cutout insets delivered to the Composable. Devices default to on and always show system UI, even with insets off.
  off delivers zero system bar and cutout insets; keyboard and gesture insets are preserved. The app decides its own padding and edge-to-edge layout.
  All device postures are available as a best-effort preview. Missing systemOverlays are assumed zero; iOS safe areas are mapped approximately to bar and cutout types.
  A missing right-landscape measurement uses the opposite landscape's horizontal mirror. These are approximations, not a promise of exact device behavior.
  status.deviceInsets gives choice, applied, supported, approximate, note, posture, basisPosture, values (four edges per type), and evidence.
  status.size.insetProfile keeps the source measurements (null means unmeasured); verified distinguishes complete type-specific evidence from an approximation.
  The choice survives device changes, folding, rotation, source saves and a temporary return to non-device sizes. It resets when interactive ends or the tab changes.
--system-ui draws or hides the status and navigation bars for original, preset and custom sizes; annotated follows @Preview(showSystemUi).
  It survives saves and resets on exit or tab change. --size original removes only the size; --system-ui annotated removes only the system UI override.
  With a device selected, --system-ui is rejected with an explanation; use --device-insets instead. A prior system UI choice is restored when returning to a non-device size.
  status.systemUi.choice records that choice, annotated records the source annotation, and shown reports whether bars are actually displayed.
  Device bars may be drawn by the viewer over the PNG. Inspect the browser for their appearance and status.deviceInsets.values for the app's input.
Giving only --size, --device, --system-ui or --device-insets turns the card on (--on is the default). Running --on again without these options keeps the choices.
The current size is in status's size (null means as in the source). hingeDp is only where the viewer draws the hinge line —
the renderer has no fold (FoldingFeature), so hinge-aware layouts aren't verified. Only the width and the window size class change.
