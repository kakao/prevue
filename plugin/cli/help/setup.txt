prevue setup [--offline]

Downloads and assembles the toolchain (renderer · layoutlib · Kotlin compiler). Once per machine. Needs the user's approval — the question to put is the ask in the health response.
--offline builds only from what was already downloaded (start does the build after a plugin update itself). With a file or --variant it doesn't run and
sends you to warmup (exit 2) — downloading from the external network and running Gradle in the target repository are separate approvals.
On success {"ok":true,"toolchain":true,"alreadyHad":…} — alreadyHad means it was already there and finished in seconds. On failure, error and the Gradle output above it.

If the person asks more
  About 435MB, around 30 seconds. Downloads layoutlib · the Kotlin compiler from Google (dl.google.com) and Maven Central. No company repository credentials needed.
  Kept in ~/.prevue/toolchain/ and not downloaded again on plugin updates. prevue paths shows where and how much.

JDK
  Follows JAVA_HOME; without it uses the daemon's JDK — PREVUE_JDK, else Android Studio's bundled JBR, else a JDK 21+ found in
  Library/Java/JavaVirtualMachines · Homebrew's openjdk · SDKMAN (25 first, then 21–24, then 26+). Nothing to set once one is installed.
  Previews are byte-identical on AS's JBR 25.0.2 · Temurin 21 · Temurin 25. 25 or later starts about a second faster (class cache).

When it fails
  The JDK is older than 21 — java -version. JAVA_HOME pointing at 17 is the default in the AGP world. Unset it, or install brew install openjdk@25 and Prevue finds it
  The network is blocked — it must reach dl.google.com · repo1.maven.org. Behind a proxy, Gradle reads HTTP_PROXY
  Otherwise the lines of the Gradle output starting with "> " are the cause — show them to the person as is
