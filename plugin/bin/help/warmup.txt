prevue warmup <file> [--variant V] [--resources-from :m] [--module :m] [--project <directory>] [--show] [--no-open]

Runs Gradle once in the target repository to take that module's classpath dump (once per module). Requests for company dependencies may go out, so it needs the user's approval —
the question to put is the ask in the health response. Add only the flags the person chose (health's next is already that command).
When --show is on the next of a show request, it opens the preparation screen first and, after the dump, goes on to bring up the preview. A plain warmup only takes the dump in the terminal.
With --show and no file, it goes to file search after preparing. --no-open doesn't open the browser automatically.
If a viewer tab was viewing this daemon, --show opens no new preparation screen either — that tab shows "restarting" and then reattaches to the new daemon (reattached:true).
It doesn't change the target repository's build files (the script is injected from outside). The variant is the debug variant compiled most recently in that module —
if that's wrong it shows the moment the screen comes up, and then change it with --variant. A clean repository guesses debug, and if Gradle names candidates it picks once more by the same rule.
If there are several resource APK candidates it narrows them to the apps containing this module, and if still several it comes back with need:"choose" and ask · options — giving the chosen one as --resources-from remembers it.
--module only when the derivation is wrong (a repository that moved projectDir). With only --module it finds the repository from the current directory — giving the file is safer.
The dump records fingerprints of the build files (settings · root · that module's build.gradle, gradle.properties, libs.versions.toml) — when they change, health asks to take the dump again.
If a daemon started by this checkout (including other agents with the same release installed) is drawing that module, it is stopped (stoppedDaemons) — it holds the old dump, so next's start starts a new one. Daemons of other checkouts are only reported in otherDaemons.
On success next is prevue start --classpath … --show <file> with this dump — it holds the chosen variant · resource provider · module, so run it as is. gradleJdk · gradleJdkFrom say which JDK it ran on — the Gradle daemon that built this module's outputs →
the JDK Prevue used last time → project settings → the shell's java, in that order. If it took minutes and gradleJdkFrom is marked "guessed", ask which JDK they usually build with and give it as JAVA_HOME.

If the person asks more
  Gradle runs once in the target repository. It is called with the JDK that just built this project, so the outputs already built are reused as is. Dependency requests may go to the company repository.
  Nothing is left in the repository — results are written under ~/.prevue/projects/. For a module never built it takes as long as the pending compilation
  (5 seconds right after a build, 4 minutes in a worktree five days old). Android Studio also runs Gradle once when it opens a project.

On failure error has the cause Gradle wrote, with Gradle's output above it — it is diagnostic material, so show it to the person as is without paraphrasing.
If the classpath lacks that module's Kotlin outputs, the dump stops itself — don't suspect the module name · variant (they're usually right); pass on the output listing which candidates it searched.
When it fails
  compileClassPath came out empty — runtime jars have no .kotlin_module, so top-level functions can't be found. Take it again
  It picked a release variant — give a debug variant with --variant (release · minify strip the source info that links clicks to code)
  The module has no android extension — it doesn't apply to pure JVM modules
  It is a KMP module — warm up with a file of the Android app module that includes it. The app dump also watches commonMain · androidMain and draws that module's previews
  It is a KMP module with no Android target — previews are drawn from the Android compilation (as in Android Studio). Pass it on to the person as is
