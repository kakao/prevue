# 뷰어 구조 시안

기능과 동작은 그대로 두고 화면마다 무엇이 어디에 놓이는가만 정한다(D-94). 한 화면씩 사용자가 확정한다. 띄우는 법은 상위 `README.md`와 같고, 목록은 `index.html`이다.

## 확정

| 화면 | 확정한 안 | 같이 정한 것 |
|---|---|---|
| 헤더와 탭 줄 | C — 프로젝트 한 줄 + 왼쪽 파일 레일(200px) | 돋보기를 뺀다. 빠른 열기 입구는 레일의 "파일 열기 ⌘K"와 `/` · `⌘K` |
| 보드 | A — 묶음이 가로로 흐른다 | 머리는 함수 이름 옆에 장 수 · 배율, 이름표는 두 줄(`name=` · 조작 버튼 / 크기 · 다크 · 글자 배율) |
| 작업 공간 | C — 레일을 접고 오른쪽 검사 패널 | 확대 · 크기 · 기기 · 자세가 패널에 선다. 패널 모양은 `panel.html`에서 이어 정한다 |

| 기기 · 프리셋 고르기 | 1 — 한 목록, 기기는 Android · iPhone 두 그룹 | 프리셋 넷(@Preview · 320×640 · 673×841 · 커스텀) 아래 기기 열. 행마다 비율 윤곽 · dp. 창 크기 구간 표시(C · M · E)는 단축키 키캡처럼 보여 뺀다(사용자). 태블릿은 Android에, iPhone Duo는 iPhone에 둔다. 긴 이름은 줄이고 툴팁에 전체 이름 |
| 빠른 열기와 시작 화면 | 1 — 가운데 팔레트 | 화면 위 가운데에 뜨고 뒤를 막(scrim)으로 가린다. 탭 0개의 시작 화면은 같은 상자가 막 없이 본문에 놓인다. 결과 줄 모양 · 매칭 · 키보드 흐름은 그대로. D-56의 "가운데 팔레트 기각"(헤더 검색창의 발견성)은 돋보기를 걷어 이유가 사라졌다 |

| 준비 화면 | 1 — 가운데 한 줄기 + 네 칸 막대, 차분한 그림 + 헤더 첫 줄 | 실제 준비 장면 위에 "지금 하는 일 · 지난 시간" 한 줄과 네 칸 막대(지금 칸은 단계 안에서 차오름), 실패하면 그 칸이 빨개진다. 조각이 모여 완성되는 움직임은 그대로이고 색은 크롬과 같은 무채색 역할 이름, 빛 띠는 걷는다. 위에 다른 화면과 같은 워드마크 줄. 화면이 아는 것(단계 · 시작 시각 · 파일 · 원인) 밖의 정보는 보이지 않는다 |
| 준비 → 보드 전환 | 3 — 떠오르기 | 그림을 카드 자리로 날리지 않는다(지금의 hero · 도착 빛을 걷는다). 보드는 처음부터 준비 화면 아래에 있고, 준비 화면이 걷히며 카드가 `--motion-enter-shift`만큼 아래에서 `--motion-stagger` 칸 수대로 떠오른다. 움직임 줄이기면 이동 없이 페이드만 |

## 범위가 바뀐 것

- **좁은 창은 시안에서 뺀다**(사용자). 지금 코드의 좁은 창 동작은 지우지 않고 그대로 둔다. 640px 아래 기준과 작업 공간 조각의 좁은 창 묶음 접힘 규칙이 빠진다.
- **커스텀 크기 슬라이더를 넣는다**(사용자) — 기능 추가라 범위 밖으로 뺀 것의 예외다. 끄는 동안은 틀만 따라오고 놓을 때 한 번 그린다(크기 바꿈 → 새 그림 0.80~0.92초, 2026-10-21 Pearl 실측).

- **기기를 여섯 더한다**(사용자) — Pixel 9 · Pixel 9 Pro Fold · Pixel Tablet · iPhone 17 · iPhone Air · iPhone 17 Pro Max. 데몬 `DeviceModel` · CLI `--device` · 뷰어 몸체 그림 · 테스트에 함께 들어가는 기능 추가라 배치 작업과 따로 둔다. 밀도(dpi)와 iPhone 포인트 크기는 그때 확인한다(시안의 ≈ 값).

## 다시 여는 동작

- **기기를 고른 동안 치수선이 읽기 전용인 것** — 숫자를 누르면 기기의 지금 크기로 커스텀에 들어간다(사용자).
- **탭 폭 규칙**(글자를 재 88~240px, 긴 탭부터 깎기, 120px 아래 가로 스크롤) — 레일에서는 뜻이 없다. 이름 가운데 줄임(꼬리 남기기)은 남는다.
