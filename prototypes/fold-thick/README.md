# 접기 장면 두께 판 시제품

접히는 판에 두께를 주면 접기 장면이 종이처럼 보이지 않는지 눈으로 보는 정적 페이지입니다. 제품 뷰어(`plugin/viewer/`)가 아니고 데몬과 이어지지 않습니다. 이 시제품이 저장소에 있다는 것이 제품 장면에 옮긴다는 결정은 아닙니다.

## 띄우기

기기 표(`plugin/viewer/js/devices.js`)와 그림(`prototypes/resize/img`)을 상대 경로로 읽으므로 **저장소 루트**에서 띄웁니다.

```sh
python3 -m http.server 8794 --bind 127.0.0.1
```

http://127.0.0.1:8794/prototypes/fold-thick/ 을 엽니다.

비교 기준은 이 체크아웃의 실제 뷰어입니다(`prototypes/resize`는 옛 갈래라 지금 장면과 다릅니다). 옆 창에 띄워 카드를 인터랙티브로 열고 같은 기기를 접어 봅니다.

```sh
(cd plugin/daemon && ./gradlew --offline installPrevue)
plugin/bin/prevue show fixtures/pearl/core/ui/src/main/kotlin/com/example/pearl/core/ui/PillNavBar.kt
```

## 써 보기

| 입력 | 하는 일 |
|---|---|
| 기기 단추 | Fold8 · iPhone Duo |
| 접기 · 펼치기 · `F` | 제품 장면과 같은 이징 · 길이로 접고 편다. `Space`는 방금 것을 다시 |
| 속도 · `S` | 1× · ½ · ¼ · ⅒ |
| 각도 | 0~180°에서 멈춰 놓고 본다 |
| 축 뒤집기 · `A` | 같은 기기를 높이로 가른다(조개형). 커버는 반쪽과 같은 크기로 둔다 — 축 경로 검증용. `hinge.axis`가 `height`인 기기는 뒤집지 않아도 같은 경로로 그린다 |
| 두께 · 닫힌 틈 | 판 하나의 두께와 다 접혔을 때 두 화면 사이 틈(dp) |
| 모서리 띠 · 띠 경계 보기 | 둥근 모서리 하나를 근사하는 띠 수(1~16)와 띠 윤곽선 |
| 빛 방향 · 높이 | 면 법선과 내적하는 빛의 각도 |
| 기울임 X · Y | 장면 전체를 돌려 두께와 옆면을 본다. 제품 장면은 0이다 |

왼쪽 위에 최근 접기의 프레임 시간(평균 · 최악 · 17.5ms를 넘은 프레임 수 — 60fps는 16.7ms이고 떨림을 봐준 값)이 나옵니다.

주소로도 같은 상태를 만듭니다 — `?dev=duo&th=135&axis=flip&tx=20&ty=-30&seg=4&T=40&wire=1&play=1`.

## 어떻게 그리나

- **판 하나가 상자입니다.** 앞면(화면) · 뒷면 · 옆면 띠로 만들고 CSS `preserve-3d`로 세웁니다. 옆면은 직선 변마다 한 장, 둥근 모서리는 호에 외접하는 띠 n장입니다. 이웃 띠는 0.6px 겹칩니다.
- **명암은 계산합니다.** 면마다 법선을 CSS와 같은 회전 행렬로 화면 좌표에 옮겨 빛과 내적합니다. 정면을 보는 면이 1이 되게 맞춰, 멈춘 화면의 밝기는 그대로이고 돌아간 면만 달라집니다. 화면은 몸체보다 덜 어두워집니다.
- **책등**은 두 판의 뒤쪽 힌지 모서리를 잇는 띠 한 장입니다. 펼치면 폭이 0이고 다 접히면 두께 둘 + 틈입니다.
- **기기 이름으로 가르지 않습니다.** 치수는 기기 표에서, 두께 · 축 · 틈은 아래 덧붙임에서 읽습니다.
- **제품 장면과 같은 값** — 원근 3200px, 원근 중심 = 힌지 선의 가운데, 이징 `bezier(.42, 0, .18, 1)`, 몸체 배율 1.6, 힌지 쪽 모서리가 20~160°에 생기는 것, 바닥 반쪽 폭이 커버 폭으로 줄어드는 각도(Fold8 90° · Duo 150°부터), 카메라 구멍 자리(`plugin/viewer/js/resize-scene.js`의 `P` · `rigAt` · `drawRig` · `drawDuo` · `camBox`). 접기 길이와 줄어드는 각도는 제품이 기기마다 달리 써서 `OVERLAY`의 `dur` · `shrinkFrom`으로 옮겼습니다.

## 스펙에 더할 후보

사이트에 없는 값이라 `look`에 손으로 적는 필드입니다. 지금은 `index.html`의 `OVERLAY`에만 있습니다 — `plugin/devices`에 모르는 필드를 넣으면 뷰어 생성이 실패합니다.

```json
"look": {
  "thickness": 26,
  "hinge": { "axis": "width", "gap": 2 }
}
```

- `thickness` — 펼친 판 하나의 두께(dp). Fold8 26 · Duo 28은 어림값입니다.
- `hinge.axis` — 힌지가 폭을 가르면 `width`, 높이를 가르면 `height`.
- `hinge.gap` — 다 접혔을 때 두 화면 사이 틈(dp). 책등 폭은 `2 × thickness + gap`으로 나옵니다 — 힌지 굵기를 따로 적지 않습니다.

## 알아 둘 것

- **판은 딱딱한 상자가 아닙니다.** 펼친 반쪽과 커버의 dp 크기가 달라(Fold8 466×704 대 475×751, Duo 475.5×669 대 466×678) 접는 동안 판 크기를 보간합니다. 제품 장면과 같고, 두께만 고정입니다.
- **90° 근처에서 선 판이 바닥 판보다 길어 보입니다.** 원근 3200px에서 판 끝이 보는 쪽으로 400px쯤 나와 1.15배쯤 커집니다. 제품 장면도 같은 배율이지만 두께가 없어 그 순간이 안 보였습니다.
- **힌지 쪽 테두리는 두 판이 서로 파고듭니다.** 접는 동안 힌지 쪽 베젤이 축을 넘어 생기는데 색이 같아 한 덩어리로 보입니다.
- **둥근 힌지 쪽 모서리에는 책등이 없습니다.** 책등 띠가 직선 구간만 덮습니다.
- 옆 단추 · 힌지 선 · 화면 그림의 흐림 교체는 없습니다. 카메라 구멍은 화면 면 위의 납작한 원입니다. 맞춤 배율도 접는 동안 고정입니다.
- `preserve-3d` 아래에는 `overflow` · `filter` · `mask` · `opacity`를 두지 않았습니다 — 조상에 있으면 납작해집니다. 둥근 자르기는 면 안에서만 합니다.
